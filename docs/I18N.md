# I18N — språkmodulen

## Struktur

```
app/Core/Translator.php   Central modul: locale-val, hämtning, parametrar, plural
app/Lang/sv.php           Svenska — standardspråk och fullständig fallback
app/Lang/es.php           Spanska
app/Lang/ru.php           Ryska (månadsnamn i genitiv; 3 pluralformer)
app/Controllers/LangController.php   POST ?page=set_lang (språkbyte + säker retur)
```

Alla filer är UTF-8 utan BOM. Hjälpfunktioner i `app/bootstrap.php`:
`t('nyckel', ['param' => …])` och `tp('nyckel', $antal)` (plural).
Vyer escapar alltid resultatet: `View::e(t(...))` — språkfilerna innehåller
enbart vanlig text, aldrig HTML.

## Tillgängliga språk och val

| Kod | Språk | |
|---|---|---|
| `sv` | Svenska | standard och fallback |
| `es` | Español | |
| `ru` | Русский | |

Valet görs i språkmenyn i headern (details/summary — fungerar utan
JavaScript, tangentbordsnavigerbar, `aria-current` på aktivt språk) eller
på inloggningssidan. Bytet sker via **POST** `?page=set_lang` med centralt
CSRF-skydd och whitelistad locale.

**Lagring:** `$_SESSION['lang']` + cookien `TIMERAPPORT_LANG`
(1 år, `HttpOnly`, `SameSite=Lax`, `Secure` vid HTTPS, path
`/time_raportDev/`) — valet överlever utloggning och stängd webbläsare.
Upplösningsordning: session → cookie → `sv`. Ogiltiga/manipulerade värden
faller alltid tillbaka till svenska. `cal_login.lang` läses/skrivs INTE
(tabellen är read-only för appen).

**Retur-URL:** `LangController::safeReturnUrl()` bygger om måladressen
från en parsad, whitelistad sidnyckel + kända parametrar (`week`,
`resid`) — rå indata når aldrig Location-headern ⇒ open redirect omöjlig.

## Nycklar, fallback och plural

- Nycklarna är stabila punktnycklar (`week.title`, `status.approved`, …)
  och identiska i alla tre filerna (verifieras av `scripts/lang_check.php`).
- Saknas en nyckel i aktivt språk används svenska; saknas den helt
  returneras nyckeln själv (syns i dev, ofarligt i drift).
- Parametrar skrivs `{namn}`: `t('dash.hello', ['name' => $name])`.
- Plural: `tp('unit.hours', 3)` slår upp `unit.hours.<form>`:
  sv/es använder `one/other`; ru `one/few/many` (1/2–4/5–20-regeln,
  decimaler → `few`), alltid med `.other` som sista fallback.
- Forcerat språk: `t('nyckel', [], 'sv')` — används av rapportmailet.

## Lokaliserade datum

Veckodagar, månadsnamn, dagrubriker och veckointervall byggs från
språkfilernas mönster (`date.day_heading`, `date.range_same/-cross`) i
`TimeFormatter::formatDayHeading()` och `ScheduleService::weekRangeLabel()`
— **ingen `intl`-beroende**. All affärslogik (ISO-veckor,
Europe/Stockholm, hourOffset, timberäkning) är oförändrad; endast
presentationen översätts. Kunddata (namn, adresser, kommentarer)
översätts aldrig.

## Statusnycklar

`is_pending` mappas till språkneutrala nycklar i
`ReportService::STATUS_KEYS` (`draft/submitted/approved`, plus `invalid`
för ogiltig tid). Logik och CSS-badges (`View::badgeClass`) jämför
nycklar; etiketten hämtas via `t('status.<nyckel>')`.

## Medvetet oöversatt

- **Rapportmailet** (`ReportService::buildEmailHtml`): alltid svenska —
  det går till den administrativa godkännandeprocessen
  (jobb@hemfresh.se) som arbetar på svenska; veckoetiketten byggs
  explicit med `'sv'`.
- Produktnamnet "HemFresh TimeRapport" och språknamnen i väljaren
  (endonymer: Svenska/Español/Русский).
- `assets/app.js` har "Skickar…" som fallback om `data-i18n-sending`
  saknas (attributet sätts översatt i layouten).
- Loggmeddelanden (`storage/logs/`) — endast för utvecklare/admin.
- Dokumentationen i `docs/` (svenska).

## Lägga till ett nytt språk

1. Skapa `app/Lang/<kod>.php` med samtliga nycklar (kopiera sv.php).
2. Lägg till koden i `Translator::LOCALES` och i den literala filkartan i
   `Translator::strings()`.
3. Lägg till `lang.<kod>` (språkets namn) i ALLA språkfiler.
4. Behövs fler pluralformer: utöka `Translator::pluralForm()`.
5. Kör `php scripts/lang_check.php` (nyckelparitet + rendering).

## Ny översättningsnyckel

1. Lägg nyckeln i `sv.php` först (svenska är källan), sedan i `es.php`
   och `ru.php`.
2. Använd `t()`/`tp()` i vyn/controllern, alltid genom `View::e()` i HTML.
3. Kör `php scripts/lang_check.php` — den failar på paritetsdiff.

svenskt rapportmail. HTTP-verifierat: CSRF-403 vid språkbyte,
